# owui-archive — Open WebUI 对话归档阅读站

把一个 Open WebUI 账号下的全部对话定时同步到本地，提供一个**只读**的阅读界面。
没有聊天输入、模型、RAG、用户管理等任何功能，只做归档和阅读。归档内容不可修改；阅读端会写入服务器的只有两样：每个对话读到哪里，以及收藏了哪些消息。

## 功能

- **自动同步**：每 N 分钟通过 Open WebUI 的 HTTP API 增量拉取（只下载 `updated_at` 变化的对话），也可在页面左下角手动触发
- **只增不删**：源站删除的对话在归档里保留，并标记「源站已删除」；同步失败不会影响已有数据
- **完整保留**：原始 JSON 全量入库（包括所有重新生成的分支）、文件夹、置顶、已归档状态、标签、图片与附件
- **阅读**：Markdown、代码高亮、LaTeX 公式、思考过程 / 工具调用折叠、分支切换、引用来源、深浅色、手机端、打印
- **阅读辅助**：对话内查找（含未展开的思考过程和工具结果）、带小标题的目录、阅读进度与续读、字号 / 宽版 / 代码换行、长代码折叠、图片放大与翻页、相邻对话跳转、收起侧栏、单条消息链接、键盘快捷键
- **全文搜索**：SQLite FTS5（trigram，支持中文），标题 + 正文 + 思考内容；一个对话里的多处命中逐条列出，可按模型和时间筛选
- **收藏**：给单条消息加星标，侧栏的「收藏」里集中查看，各设备共用
- **导出**：单个对话导出 Markdown 或原始 JSON；侧栏底部可一次导出整个归档（JSON 可重新导入 Open WebUI）
- **概览**：首页显示近 12 个月新建的对话数、各模型参与的对话数，以及按模型统计的字数和 token 用量（手机上首页是对话列表，点列表顶上的数字卡片进入）
- **离线可读**：读过的对话、最近的一批对话和页面本身会存在浏览器里，断网或服务器连不上时照常打开
- **访问控制**：单一密码，登录后 30 天有效

## 阅读辅助

打开一个对话后，右上角（手机上在顶栏）有三个按钮：查找、目录、阅读设置。

- **对话内查找**：不区分大小写，会搜到还没展开的思考过程和工具调用结果，并自动展开到命中处。从侧栏的全文搜索结果点进对话时，会直接定位并高亮搜索词
- **目录**：列出这个对话里的每一次提问，以及回答里的各级标题，点击跳转；当前读到的位置会高亮
- **阅读进度**：顶部细线显示进度；每个对话读到哪里会记下来，侧栏顶部的「继续阅读」列出最近读到一半的对话，刷新页面也会回到原位
- **跨设备续读**：阅读位置会同步到服务器，换一台设备打开就能接着读；切回一个开着的标签页时，如果别的设备读得更远会有提示。离线时先记在本机，联网后补传，较旧的位置不会覆盖较新的
- **阅读设置**：正文字号（90%–135%）、宽版布局、代码自动换行、一键展开 / 收起所有思考过程和工具调用
- **图片**：点击在页内放大，再点一次看原始大小；同一对话里的图片可以用按钮、`←` `→` 或左右滑动翻页
- **长代码块**：超过 40 行的代码默认只显示开头，点击展开；复制、查找不受影响
- **相邻对话**：对话末尾有「较新 / 较早的对话」入口，按更新时间排序
- **收起侧栏**（桌面端）：侧栏右上角的按钮可以收起对话列表，正文居中显示；顶栏左侧的按钮或 `/` 再展开
- **收藏**：每条消息下方的星形按钮；收藏后侧栏出现「收藏」标签，点某一条直接跳到那条消息（最多 2000 条）
- **筛选**：搜索框右侧的按钮展开筛选行，可按模型、时间范围过滤对话列表和搜索结果；首页概览里点某个模型也会按它筛选
- **日期分隔**：跨天的对话在换日处显示日期
- **源站已删除**：有对话在源站被删除后，侧栏会多出一个筛选，列出这些只存在于归档里的对话
- **消息链接**：每条消息下方可以复制指向这条消息的链接（`#/c/<对话>/m/<消息>`）

快捷键（不在输入框里时）：`J` / `K` 下一条 / 上一条消息，`F` 对话内查找，`O` 目录，`E` 展开 / 收起全部折叠块，`G` / `Shift+G` 顶部 / 底部，`[` / `]` 较新 / 较早的对话，`/` 搜索全部对话，`Esc` 关闭当前浮层。

阅读位置保存在服务器的 `reading` 表里（最多 500 个对话），收藏保存在 `stars` 表里。两者都是所有登录的设备共用一份——本站只有一个密码，没有用户之分。字号、宽版、侧栏收起等阅读偏好仍然只保存在当前浏览器，各设备可以不同。

## 离线可读

页面注册了一个 Service Worker（`public/sw.js`），需要 HTTPS 或 `localhost`；用 `http://局域网 IP` 访问时浏览器不提供这项能力，其余功能不受影响。

- **存什么**：页面本身（脚本、样式、公式字体）；对话列表、收藏、统计；打开过的对话和其中的归档图片（每个对话最多 12 张、共 8 MB，单张不超过 5 MB）；另外在后台预存最可能要看的约 30 个对话——读到一半的、收藏过的、置顶的、最近的（只存正文，超过 1 MB 的跳过）。同步后对话有变化，缓存里的那份会自动换新。
- **什么时候用**：一律先问服务器。断网、网关报 502 以上、接口被强制门户换成网页时改用缓存；服务器超过 3 秒没有回应而手里有缓存时，也先显示缓存，请求照常跑完留给下次。此时侧栏底部写着「离线 / 连不上服务器 · 显示已缓存的内容」，没有缓存的对话在列表里划掉；恢复后自动回到在线状态。
- **离线时做不了的**：全文搜索（退化为只搜标题，并注明）、收藏（会提示没有保存）、同步、导出。阅读位置照常记在本机，联网后补传。
- **不想让它主动下载**：阅读设置里关掉「预存最近的对话」，就只保留打开过的；浏览器的省流量模式下、以及能识别出是移动网络时也不会预存。
- **清理**：退出登录或会话失效时，存下的对话全部删除；缓存只在登录有效期内可读（到期即作废）。离线时点退出会先清掉本机缓存并回到登录页，下次联网打开时再把服务器上的会话结束掉。上限为 1000 条 / 约 300 MB，超出后从最旧的删起。

## 字数与 token 统计

首页的「字数与 token 用量」按模型列出回答数、字数、输入和输出 token（接口：`GET /api/stats`）。

- **字数**按中文习惯计：每个汉字（含假名、谚文）算 1 字，一串连续的字母或数字算 1 词，标点和空白不计。与上游返回的 token 数无关。
- **token**：上游返回了用量（`usage` 里的 `prompt_tokens` / `completion_tokens`，或 Anthropic、Ollama 的对应字段）就原样采用；没有返回的回答按模型估算，表格里带 `≈`。
- **估算方法**：按模型名匹配分词器家族（`server.js` 里的 `TOKEN_FAMILIES`），用「每个汉字约合多少 token、每个其他字符约合多少 token」两个系数由文本折算。输出包含思考内容，输入按生成那条回答时的全部上文计。系数是粗略的经验值，不是真实分词结果，误差可能达到两三成；系统提示词、工具定义、图片和附件不在归档的文本里，估算的输入不含它们。
- 所有分支都计入（重新生成的回答同样花过 token）。

## 部署

需要 Node.js ≥ 22.13（使用内置的 `node:sqlite`，无原生依赖）。

```bash
npm install
cp .env.example .env    # 填 OPENWEBUI_URL / OPENWEBUI_API_KEY / ARCHIVE_PASSWORD
npm start               # 默认 http://127.0.0.1:8090
```

API Key：Open WebUI「设置 → 账号 → API 密钥」。管理员需要在后台开启 API Key 功能；
如果开启了「API Key 端点限制」，要放行 `/api/v1/chats`、`/api/v1/folders`、`/api/v1/files`。

常驻运行：

```bash
sudo cp owui-archive.service /etc/systemd/system/
sudo systemctl enable --now owui-archive
```

默认只监听 `127.0.0.1`，适合挂在 Caddy / Nginx / Cloudflare Tunnel 后面；要直接对外，把 `.env` 里的 `HOST` 改成 `0.0.0.0`。

登录失败 5 次后会按访问者的地址限速。地址这样认：连接来自本机（同一台机器上的反向代理）时，取 `X-Forwarded-For` 最右边的一段，也就是代理自己写上去的那个；否则用连接本身的地址，请求头一概不信。反向代理在别的机器上时，在 `.env` 里设 `TRUST_PROXY=1`，否则所有访问者会被算成同一个地址。

文本类的响应（接口的 JSON、页面的 JS / CSS）由服务端按浏览器的意愿做 brotli / gzip 压缩，反向代理不必再压一遍。

## 长对话

几百条消息的对话不会一口气渲染完：开头的一段立刻显示，其余的在后台分批接上，消息列表底部和顶栏进度条上有加载进度；屏幕外的消息不参与排版。要去的位置（续读、消息链接、搜索命中、跳到底部）还没渲染到时会先提示，渲染到了再跳过去。打印前会把剩下的全部渲染出来。

读过的对话再次打开时，阅读端会把手里那一份的版本报给服务器，没有变化就不再传正文（需要 Service Worker，即 HTTPS 或 localhost）。

## 数据

全部在 `data/`（可用 `DATA_DIR` 修改）：`archive.db` 是 SQLite 数据库，`files/` 是下载的附件。备份这个目录即可。

## 同步逻辑

每轮同步：

1. 拉取文件夹列表
2. 遍历 主列表 / 每个文件夹 / 已归档 / 置顶 四类列表（只有 id 和时间，很轻）
3. `updated_at` 与本地不同的对话才拉取全文；文件夹归属、置顶、归档状态每轮都按列表校正
4. 本地有、源站列表里没有的 → 标记「源站已删除」，不删除
5. 下载新对话引用的附件（单个上限 `MAX_FILE_MB`）

任何一步列表请求失败，整轮放弃，不会误标删除。
